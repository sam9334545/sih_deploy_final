# Assumptions register

Every number in this system is one of four things: **measured** (from an official
published record), **derived** (computed by a model from measured inputs),
**estimated** (a documented judgement where no publication exists), or
**expert_set** (a hand-curated parameter). This file lists every judgement call.
The API returns the relevant subset in each response's `assumptions` array, so a
user never sees a number without seeing what it rests on.

## Physical and operational

| Parameter | Value | Why | Where |
|---|---|---|---|
| Under-keel clearance | `max(0.5 m, 10% of static draft)` | Standard commercial convention for dry bulk; ports do not publish a single UKC rule | `config.ukc_fraction`, `ukc_min_m` |
| Vessel constants (bunkers, stores, fresh water) | 1,800 / 2,400 / 3,000 / 6,000 t by class | Deducted from deadweight before cargo intake | `data/reference/vessel_classes.csv` |
| TPC (tonnes per cm immersion) | Per class, from the Baltic standard vessel descriptions | Gives the deadweight-vs-draft relationship from the same source as the index we forecast | same file |
| Laytime | Published handling rate × 1.15 | Customary allowance; waiting inside laytime is not demurrage | `cost_model.laytime_days_for` |
| Demurrage rate | $9k / $14k / $18k / $28k per day by class | Market convention, user-editable | `vessel_classes.csv` |
| Waiting cost inside laytime | 35% of the demurrage rate | Waiting is real cost to the charterer before it becomes a claim | `cost_model.voyage_cost` |
| Charter lead time | 10 days | Time to fix a ship and get it to the laycan | `config.charter_lead_time_days` |
| Sandheads lighterage rate | 9,000 t/day plus 1.2 days transit | Floating-crane throughput and the ~125 km Sandheads–Haldia leg | `config` |
| Self-congestion | +12% expected wait per prior voyage of the same ship at the same berth | More of your own calls means you queue behind yourself | `simulator.simulate` |
| Parallel execution stagger | 3 days between ships | Berth scheduling reality | `simulator`, `deadline_feasible` |
| Severe part-load flag | intake < 50% of class deadweight | Commercially, not physically, the threshold | `config.severe_partload_ratio` |
| Stranded parcel flag | final parcel < 60% of intake | A badly stranded last parcel is a real cost | `config.stranded_parcel_ratio` |
| Fleet-mix cap | at most 2 classes | Practical for a single requirement | `config.max_classes_in_mix` |

## Commercial

| Parameter | Value | Why |
|---|---|---|
| Multi-voyage contract discount | 5% off freight | The volume discount a COA typically buys; user-editable |
| COA variance reduction | residual variance × 0.35 | A fixed rate sheds most, not all, of the rate risk (the operational terms still vary) |
| Risk aversion λ | 0.5 default, 0–1 | Weight on `CVaR90 − mean`. User-visible, and `/opportunity-score` reports how the answer moves across the whole range |
| Deadline-miss penalty M | $500,000 default | The user's own cost of missing the cargo deadline; user-editable |
| Shadow freight margin | 0.09–0.15 by lane | The single free parameter of the shadow freight model, fitted against a publicly quoted route |
| Backhaul index | 0.15–0.45 by lane | Expert-set 0–1: how often the ship finds a paying cargo home. 1.0 = no ballast premium |

## Data standing in for a feed

| What | Status |
|---|---|
| Freight indices, commodity and macro series | `simulated_demo` seeded series with realistic statistical properties, generated by `scripts/generate_demo_series.py`. Replace with the real ingestion output; the schema is identical |
| Port call waiting times | `simulated_demo` for every port. The real pipeline parses the published daily traffic reports — Paradip's are the best-in-class source |
| Private-port tariffs (Adani terminals) | `estimated`. These operators do not publish a full scale of rates; the API returns `provenance: "estimated"` wherever they are used |
| AIS vessel positions | Not used at all. No free source with usable coverage and licensing was found, so the system is designed not to need it |

## Deliberate non-assumptions

- No weights are invented for the compatibility score: it is a product of four
  ratios that each have a physical meaning.
- No weights are invented for the risk score: they come from a ±1σ sensitivity
  analysis of the simulator on the scenario being scored.
- No cut-offs are invented for LOW/MEDIUM/HIGH: they are tertiles of each
  component's own historical distribution.
- The Charter Opportunity Score is not a weighted sum: it is a percentile rank of
  a computed cost across the remaining decision window.
