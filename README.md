# SIH26006 — Intelligent Freight Forecasting & Charter Decision Support System

Modular repository architecture for SIH26006, designed for high maintainability, strict separation of concerns, and reproducible data workflows.

---

## Workspace Structure

```text
SIH26006/
├── ml-work/
│   ├── data/
│   │   ├── raw/                       # Immutable raw observation data
│   │   │   └── original_dataset.csv
│   │   └── processed/                 # Standardized, cleaned data ready for ML training
│   │       └── bpi_cleaned.csv
│   ├── pipeline/                      # Pure-function, config-driven cleaning & audit package
│   ├── scripts/                       # CLI scripts for cleaning and audit
│   │   └── run_pipeline.py
│   ├── tests/                         # Data pipeline unit tests
│   ├── DATA_PROVENANCE.md             # Data source and benchmark provenance audit
│   ├── CLEANING_REPORT.md             # Execution report generated by the pipeline
│   └── README.md                      # Developer guide for adding/correcting observations
│
├── backend-work/                      # FastAPI service & simulation decision engine
│   ├── app/                           # Routers, schemas, repositories, and business logic
│   ├── data/reference/                # Static port, berth, route, and tariff reference tables
│   ├── tests/                         # API and decision engine integration test suite
│   ├── Dockerfile
│   └── charter.db                     # SQLite database seeded from reference tables
│
└── frontend-work/                     # Frontend client workspace
    ├── src/                           # UI components, dashboard, and simulation views
    └── README.md                      # Frontend setup and integration guide
```

---

## Architectural Principles

1. **Strict Data Separation**:
   - `ml-work/data/raw/` is never modified or overwritten by scripts.
   - Cleaned datasets are written deterministically to `ml-work/data/processed/`.
2. **Reproducible & Config-Driven**:
   - Zero hard-coded observations in code.
   - Any team member can append, edit, or remove raw rows and run `python ml-work/scripts/run_pipeline.py`.
3. **Decoupled Tiers**:
   - Changes to ML datasets or feature logic require zero modifications to `backend-work/` or `frontend-work/`.
   - The backend serves standard contracts independently of ML training runs.
